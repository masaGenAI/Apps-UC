# 収益化と計測（Lv.4以降）

技術より先に、**何で稼ぐか**を決めます。個人開発で現実的なのは次の4つです。

| モデル | 向いているアプリ | 手取りの目安 | 難易度 |
|---|---|---|---|
| **サブスク（月額/年額）** | 毎日/毎週使う記録・学習・健康系 | 最も大きい。継続課金が積み上がる | 高（継続率の設計が要る） |
| **買い切り（1回課金）** | 道具系・ユーティリティ | 単発。DL数に比例 | 中 |
| **広告（AdMob）** | 暇つぶし系・DL数が多いもの | 1万DLでも月数千円規模。**主軸にしない** | 低 |
| **無料+有料版の2本立て** | 買い切りの代替 | 中 | 低 |

> **ストア手数料は売上の15〜30%**（Apple / Google とも、小規模開発者向けの低減プログラムあり = 概ね15%）。
> 価格設定はこの手数料と、サブスクならAPI原価を引いた上で考えます。

---

## 1. RevenueCat（課金の実装）

iOSとAndroidの課金APIは仕様が違い、レシート検証も必要です。RevenueCatはそれを1つのSDKに統一します。

```powershell
npx expo install react-native-purchases
```

導入の流れ：
1. App Store Connect / Play Console で**商品（プロダクト）を登録**（例：`pro_monthly` 月額480円）
2. RevenueCat のダッシュボードで両ストアの商品を **Entitlement（例：`pro`）** に紐付ける
3. アプリ側は「`pro` を持っているか？」だけを見る → ストアの違いを意識しなくてよくなる
4. **Sandboxテスト**（実際に課金せず購入フローを試す）を必ず通す
5. **「購入の復元（Restore）」ボタンを必ず設置**（Appleの審査要件）

---

## 2. Paywall（課金画面）の設計

技術より、ここが売上を決めます。

- **無料で価値を体験させてから課金を出す。**起動直後のPaywallは離脱を招く
- 無料と有料の線引き例：
  - 記録数の上限（無料は3件まで）
  - 期間（無料は直近7日分のみ閲覧）
  - 便利機能（エクスポート・クラウド同期・広告非表示・テーマ）
- **年額をデフォルト選択にし、月額比の割引率を明示**する
- 無料トライアル（3〜7日）は転換率を大きく上げる。ただし解約率も見る
- 価格は**安すぎない方がよい**。¥120 より ¥480 の方が総売上が上回ることが多い

---

## 3. AdMob（広告）

```powershell
npx expo install react-native-google-mobile-ads
```

- 開発中は**必ずテスト広告ID**を使う（本番IDで自分がタップするとアカウント停止のリスク）
- インタースティシャル（全画面広告）は **「作業の区切り」だけ**。操作の途中に挟むとレビューが荒れます
- リワード広告（動画を見ると機能解放）は、体感が最も良い形式
- 広告とサブスクは併用可：**「広告非表示」を課金の入口にする**のは定番

## 4. 計測（測らないと改善できない）

| 目的 | ツール | 見る数字 |
|---|---|---|
| 利用状況 | Firebase Analytics / PostHog | 起動数、主要機能の利用率、離脱画面 |
| 障害検知 | Sentry | クラッシュ率（**1%を超えたら最優先で修正**） |
| 課金 | RevenueCat ダッシュボード | 転換率、解約率(Churn)、MRR |
| ストア | App Store Connect / Play Console | 表示回数→DL の転換率、検索キーワード |

**最重要の2つ**
1. **翌日継続率（D1 Retention）** — 30%を切るならアプリの中身に問題がある
2. **ストアページの転換率** — 低いならアプリではなく**スクショと説明文**の問題

---

## 5. ASO（ストアで見つけてもらう）

- **アプリ名に検索される語を1つ入れる**（例：「筋トレ記録 - ジムログ」）
- スクショ1枚目で「何のアプリか」が2秒で伝わること。**文字を大きく載せる**
- 説明文の冒頭3行が検索結果に出る。ここに結論を書く
- レビュー依頼は **成功体験の直後**（記録を10回つけた後など）に `expo-store-review` で出す
- ★4.5以上を維持する。低評価には必ず返信する（Play Consoleから返信可能）

## 6. 最初の100ユーザーをどう集めるか

コードより難しく、そして決定的です。081番以降は必ずこれを企画時点で決めます。

- 対象ニッチのコミュニティ（X、Reddit、Discord、掲示板、趣味のオフ会）で**作る過程から公開する**
- 「◯◯（既存アプリ）が使いにくかったので作りました」は強い導入
- ブログ/note 1本 + デモ動画1本をリリース時に用意
- 友人・家族は**Google Playのクローズドテスト要件を満たすためにも**声をかけておく
