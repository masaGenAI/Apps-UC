# 100アプリ一覧

各行の「学ぶこと」が本体です。アプリのテーマは差し替えて構いませんが、**学ぶことの順番は入れ替えないでください**（積み上げ式です）。
完成したら行頭を `- [x]` に変えてコミットしてください。

---

## Lv.1 基礎（001–020）｜保存なし・API なし・見た目も気にしない
目標：`useState` と画面表示を手が覚えるまで。1本2〜3時間。

- [ ] 001 カウンター — `useState`、Button、onPress
- [ ] 002 チップ計算機 — TextInput、数値変換、計算結果の表示
- [ ] 003 サイコロ — 乱数、画像/絵文字の出し分け
- [ ] 004 BMI計算 — 複数入力、条件分岐による判定メッセージ
- [ ] 005 単位変換（cm↔inch） — 双方向の入力連動
- [ ] 006 ストップウォッチ — `useEffect`、`setInterval`、クリーンアップ
- [ ] 007 カウントダウンタイマー — 時間の整形（mm:ss）
- [ ] 008 じゃんけん — 勝敗ロジック、勝率の集計
- [ ] 009 おみくじ — 配列からランダム抽出、確率の重み付け
- [ ] 010 割り勘計算 — 端数処理、切り上げ/切り捨て
- [ ] 011 電卓 — 状態管理の設計（ここで初めて「設計」を意識する）
- [ ] 012 パスワード生成 — 文字種の組み合わせ、クリップボードコピー
- [ ] 013 年齢・日数計算 — 日付操作（Date）
- [ ] 014 カラーコード変換（HEX↔RGB） — 文字列処理
- [ ] 015 ランダム決定ルーレット — 配列の追加・削除（CRUDの前段）
- [ ] 016 TODOリスト（保存なし） — FlatList、key、リストの更新
- [ ] 017 メモ帳（保存なし） — 複数行入力、文字数カウント
- [ ] 018 単語カード（めくるだけ） — 表裏のトグル、次へ/前へ
- [ ] 019 4択クイズ（問題は配列直書き） — 正誤判定、スコア、リトライ
- [ ] 020 タップゲーム（10秒連打） — タイマー＋スコア、ゲームの状態遷移

**Lv.1修了チェック**：001〜020を見ずに「TODOリスト」をゼロから30分で作れるか。

## Lv.2 実用（021–040）｜保存する・画面が増える・外部データを取る
目標：「使えるアプリ」の最低ライン。1本4〜6時間。

- [ ] 021 TODOリスト（保存版） — `AsyncStorage`、アプリ再起動後もデータが残る
- [ ] 022 買い物リスト — チェック状態の保存、完了アイテムの分離
- [ ] 023 習慣トラッカー — 日付ごとの記録、カレンダー表示
- [ ] 024 簡易家計簿 — カテゴリ別集計、合計の算出
- [ ] 025 体重記録 — グラフ表示（`react-native-chart-kit` 等）
- [ ] 026 日記アプリ — 一覧→詳細の画面遷移（Expo Router）
- [ ] 027 読書記録 — タブナビゲーション（読書中/読了）
- [ ] 028 単語帳（CRUD完全版） — 作成・編集・削除・並べ替え
- [ ] 029 ポモドーロタイマー — バックグラウンド動作の考慮、設定画面
- [ ] 030 複数タイマー（料理用） — 同時進行する状態の管理
- [ ] 031 天気アプリ — 外部API（Open-Meteo等）、`fetch`、ローディング表示
- [ ] 032 為替計算機 — APIエラー時のフォールバック処理
- [ ] 033 郵便番号→住所検索 — 入力に応じたAPI呼び出し、デバウンス
- [ ] 034 猫/犬画像ビューア — 画像の非同期読み込み、お気に入り保存
- [ ] 035 ニュースリーダー（RSS） — XML/JSONのパース、外部リンクを開く
- [ ] 036 名言アプリ — 1日1回更新のロジック、共有機能
- [ ] 037 レシピメモ — 画像なしのリッチな入力フォーム、バリデーション
- [ ] 038 クイズアプリ（問題データ分離版） — JSONからの読み込み、難易度選択
- [ ] 039 パスワード管理（ローカル） — `expo-secure-store`、機密情報の扱い

- [ ] 065 画像アップロード — Supabase Storage、容量とコストの意識
- [ ] 066 リアルタイム共有リスト — 同時編集、購読（subscribe）
- [ ] 067 プッシュ通知（サーバ送信） — Expo Push、トークン管理
- [ ] 068 管理用の簡易Web画面 — Next.js、同じTypeScriptで作る
- [ ] 069 AdMob バナー広告 — 広告SDK導入、テスト広告の扱い
- [ ] 070 AdMob インタースティシャル/リワード — 表示頻度の設計（UXを壊さない）

## Lv.5 商用プロダクト（081–100）
目標：**本数ではなく売上**。1本あたり2〜4週間。作る前に必ず企画メモを書く。

### 企画メモのテンプレ（`apps/NNN-xxx/PLAN.md` に必須）
```
1. 誰が（具体的に1人を描写。「30代の〜」ではなく「週2でジムに通う会社員の田中さん」）
2. どんな不便に、いま何分/いくら払っているか
3. 既存アプリは何があり、なぜ不十分か（実際に3本ダウンロードして触る）
4. どう解決するか（画面3枚で説明できるか）
5. どこで課金するか / いくらか
6. 最初の100人をどこから連れてくるか  ← ここが書けないアプリは作らない
```

- [ ] 081–085 **ニッチ×5本**：以下から市場調査して選定（競合が「存在するが古い・評価が低い」領域が狙い目）
  - 業務ニッチ（点検記録・シフト・在庫・現場写真報告）
  - 健康（睡眠・断食・服薬・血圧記録）
  - 学習（資格試験・語学・暗記）
  - 趣味特化（釣り・ゴルフ・登山・キャンプ・推し活）
  - 子育て / ペット / 介護の記録
- [ ] 086–090 **AI活用×5本**：文章生成・要約・画像生成・音声文字起こしをアプリに組み込む
      （APIコストの原価計算とサブスク価格の設計が学習の本体）
- [ ] 091–095 **磨き込み×5本**：081–090で反応の良かったテーマを作り直す。ASO・スクショ・レビュー導線・オンボーディング改善
- [ ] 096–100 **1本に集中**：最も数字の良いアプリの改善リリース5回。
      計測 → 仮説 → 改修 → リリース → 検証 のサイクルを回す。**新規開発はしない。**

**最終ゴール**：100本目を終えた時点で「ダウンロードされ、課金され、改善が続いているアプリが1本以上ある」こと。
