# Prototype 01 — AIリテラシー＆セキュリティ・ガバナンス アセスメント（Claude）

> **元ユースケース：UC-29 AI成熟度診断サービス（外販・◆本命）＋ UC-23 AIケイパビリティ測定キット**
> 自己申告アンケートではなく、**本人が書いた実際の文章をLLMに読ませて**、AIリテラシー（6次元）と
> セキュリティ・ガバナンス意識（5次元）を**世界標準フレームワーク準拠でスコア化**する。

## 何が変わったか（v1 → v2）

| | v1（旧） | v2（本版） |
|---|---|---|
| 対象 | 組織のAI成熟度 | **個人**のAIリテラシー＆セキュリティ意識 |
| 方式 | 自己申告アンケート | **実際に書いた文章をLLMが採点** |
| 基準 | 社内資料の枠組み | **世界の主要フレームワークを調査して構築**（下記） |

> 旧・組織成熟度診断は [`index-org-maturity.html`](./index-org-maturity.html) に温存。

## 構成（2つの成果物）

### A. 採点キット（主役）— [`scoring-kit/`](./scoring-kit/)
LLMに読ませて、**簡単なプロンプトを打つだけ**で採点できるキット。
- `採点キット_SYSTEM.md` … Claudeプロジェクトのカスタム指示に貼る採点システムプロンプト＋ルーブリック。
- `rubric.json` … 機械可読ルーブリック（G5：汎用形式で外部化）。
- `使い方.md` … Project導入手順＋「打つだけ」のプロンプト例。
- `scenarios.md` … セキュリティ・ガバナンス挙動を炙り出す実務シナリオ課題5本。

### B. HTMLハーネス（可視化）— [`index.html`](./index.html)
- **公開Artifact**：https://claude.ai/code/artifact/4e85945c-23c2-45a3-a777-dad2b3ddb86d
- Step 1：文章（プロンプト／会話ログ／シナリオ回答）を入れて**採点プロンプトを自動生成**→コピー。
- Step 2：Claudeの採点結果JSONを貼り戻すと、**スコアカードを描画**：
  - AIリテラシー6次元レーダー／セキュリティ5次元バー／総合レベル
  - **検知された危険挙動（red flags）をハイライト**／各次元の根拠引用／強み・次の一手
  - スコアカード保存（`downloads` capability）。ライト/ダーク両対応・入力は外部送信なし。

## 測る11次元

**AIリテラシー（6）**：L1 仕組みと限界の理解／L2 プロンプト設計・タスク分解／L3 批判的評価・ファクト検証／L4 人間とAIの協働／L5 倫理・バイアス・社会影響／L6 適用範囲の判断。

**セキュリティ・ガバナンス意識（5）**：S1 データ分類と投入可否／S2 AI固有脅威の自覚（プロンプトインジェクション等）／S3 人間の最終判断・記録／S4 規制・契約・著作権／S5 出力の信頼性統制と外部発信。

各次元は1〜4点＋到達アンカー。セキュリティ各次元には**危険挙動（red flags）**を定義し、文章に現れたら減点・指摘する。

## 評価基準の根拠（世界のフレームワークを調査して構築）

ルーブリックは以下の共通項から構成。全出典一覧は [`research/`](./research/)（md＋xlsx、28件）。

- **リテラシー**：UNESCO AI Competency Framework（学生/教師）/ OECD・EC「Empowering Learners for the Age of AI」(AILit) / EU AI Act 第4条 / Long & Magerko (CHI 2020) / AI4K12 Five Big Ideas / DigComp 2.2 / IPA・METI デジタルスキル標準 / Elements of AI ほか
- **セキュリティ・ガバナンス**：NIST AI RMF・Generative AI Profile / ISO/IEC 42001・23894 / OWASP Top 10 for LLM Applications / MITRE ATLAS / Singapore Model AI Governance Framework / 日本 AI事業者ガイドライン ほか

> **調査の透明性**：本調査環境は外部 `WebFetch` がegressポリシーで遮断されていたため、GitHub上の一次文書（OWASP/MITRE）**4件のみ本文fetch検証済**、他はライブ検索で実在・構造を確認した**「検索確認」**扱いです。`research/` の一覧に検証ステータスを明記しています（未検証を検証済と偽らない）。

## 設計上の要点（AIエンジニアリング／セキュリティ・ガバナンスのレンズ）

- **LLM-as-judge は校正前提**：各スコアに本人文章からの**引用（evidence）を必須化**し、根拠なきスコアを禁止（ハルシネーション抑制）。
- **情報不足 ≠ 減点**：触れていないだけの項目は「情報不足」とし、危険挙動（実際に現れた危うい記述）と区別。
- **限界の明示**：1サンプルからの点推定（n=1）である旨をUIに明記。人事評価に直結させない（G2）。
