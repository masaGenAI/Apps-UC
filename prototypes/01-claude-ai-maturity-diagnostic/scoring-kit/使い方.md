# 使い方 — AIケイパビリティ成熟度 採点キット v2（型）

このキットは「**お使いのLLM（任意）に読ませて、証跡を渡すだけ**」で、AI活用型ビジネスコンサルタントの
AIケイパビリティを、**CMMI型5段階 × 10次元**で採点します。**特定ベンダーに依存しません。**

## 型（テンプレート）と会社ポリシーの差し込み

このキットは **「型」** です。**セキュリティ・ガバナンス（D9）とゲート判定は、各社が自社のガイドライン・規程を差し込んで**使います。

1. `company-policy.template.md` を複製し、貴社のデータ投入区分・AI利用規程・禁止事項・規制/契約・報告先を記入。
2. 記入した内容を `採点キット_SYSTEM.md` の「## 会社ポリシー」節に貼り付ける。
3. お使いのLLMに取り込む（下記）。
- すでに記入済みの完成版が欲しい場合は、`instances/rise/` に **Rise Consulting Group 専用インスタンス**があります（型の使用例）。

## セットアップ — お使いのLLMにインポート

| プラットフォーム | 取り込み先 |
|---|---|
| ChatGPT（Enterprise/Team/Plus） | GPTs / プロジェクトの Instructions。`rubric_v2.json` はナレッジ添付 |
| Google Gemini | Gems の Instructions |
| Microsoft Copilot | Copilot Studio のエージェント指示 |
| Claude | プロジェクトのカスタム指示／ナレッジ |
| 社内独自LLM | システムプロンプト欄に `採点キット_SYSTEM.md` 全文を貼付 |

## 採点する（証跡を渡すだけ）

証跡（Evidence）は強度で E0〜E5 に分かれます。渡せるものを渡すほど信頼度が上がります。

```
次の証跡でこの人のAIケイパビリティを採点して：
〈プロンプト／AI会話ログ／シナリオ回答／成果物／GPT設定／Deep Research計画 などを貼る〉
```

- 単一テキスト（プロンプト1つ等）＝ E0–E1（暫定評価）。
- 複数案件の成果物・GPT設定・テスト結果・利用実績＝ E3–E5（高信頼）。
- **証跡が無い次元は「情報不足(insufficient_evidence)」**として扱われ、**能力が低いとはみなされません**。

## 出力（4層）

1. **Capability Maturity**：総合成熟度 L1–5（ゲート補正あり）
2. **Capability Score**：10次元の加重合計 0–100（カバレッジ%付き）
3. **Evidence Confidence**：証跡の強さ E0–E5
4. **Business Impact**：組織・顧客への寄与（能力とは別建て。自己申告/推定/実測を区別）

末尾の機械可読JSONを、同梱の **可視化ハーネス**（`../index.html`）に貼ると、成熟度・レーダー・ゲート・違反ハイライトが描画されます。

## 10次元（何を測るか）
D1 AIリテラシー／D2 課題設定／D3 対話&プロンプト設計／D4 リサーチ&知識統合／D5 コンサル適用／
D6 GPT・エージェント設計／D7 AI支援開発&分析／D8 評価&QA／D9 Responsible AI・セキュリティ（会社ポリシー差し込み）／D10 ワークフロー&再利用。

## 設計思想（なぜこの形か）
- 単一総合点で人を序列化しない（能力／証跡信頼度／ビジネス価値を分離）。
- 証跡が無い＝能力が低い、ではない。
- Responsible AI・評価/QA・課題設定が未成熟なら、総合が高くても**ゲートで上限**を課す。
- AIエンジニアとしてでなく、**AIで顧客価値を生むコンサルタント**として評価。
- 出典：Rise向けAIケイパビリティ成熟度モデル(DeepResearch)／CMMI AIM・SFIA・AI Skills for Business・NIST・ISO・OECD・EU AI Act。

## 注意（G2：人間最終判断）
本採点は人事評価に直結させないでください。育成・自己認識・配置の**参考**であり、証跡が単一・少量のときは暫定です。最終判断と記録は人が担います。
