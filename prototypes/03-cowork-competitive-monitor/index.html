● Claude Cowork

競合モニタリング Skill

UC-05 業界ニュース・競合モニタリング配信 ＋ UC-53 競合ベンチマーク自動更新

担当業界・クライアント・競合の動きを定点で収集・検証・要約し、出典リンク付きの週次ブリーフィングを生成して配信する Cowork スキル。

収集→検証（原文リンク必須）→要約→ベンチマーク更新→配信（下書き）

ダウンロード / ソース

このキットは Cowork のスキル（SKILL.md＋参照ファイル）です。Coworkに読み込ませて使います。

⬇ SKILL.md スキル本体 ⬇ briefing_template.md 出力様式 ⬇ benchmark_table.md 比較表 ⬇ source_policy.md 出典ポリシー ⬇ watchlist.example.md 監視対象テンプレ 📄 README.md 解説

使い方（Cowork上）

  1. このフォルダを Cowork のスキルとして読み込む。
  2. watchlist.example.md を複製し、担当業界・クライアント・競合を記入。
  3. 「competitive-monitor を実行して」または「今週の競合ブリーフィングを作って」と依頼。
  4. Cowork が収集→検証→要約→ベンチマーク更新を行い、Gmail 下書き（既定）か Notion ページで出力。
  5. 「毎週月曜の朝に実行して」と依頼すれば週次ルーティン化。

なぜ「Claude Cowork」で作るのか

UC-05 は適格性テストで ルールA＝チャットで代替不可（定期起動と配信の仕組みが必要）と判定。Cowork は Web検索・Gmail・Notion などのコネクタを横断してエージェントとして作業を完結できるため、「収集→検証→要約→配信」の一連を担えます。

出力ポリシー（元資料のガバナンスに準拠）

原則 / 注記実装
UC-05「誤要約リスク→原文リンク必須」全項目に一次情報リンクを必須化。確認できない情報は載せない
UC-53「財務数値は一次情報に当たる」数値は決算資料等の一次ソースで検証。二次まとめは根拠にしない
A1（最終責任は人間）配信は下書きまで。送信・社外共有は人が承認
G1（データ投入区分）公開情報のみを対象。顧客秘密は投入しない
G6（二モデル検証・任意）重要示唆は2モデルに独立投入し相違点のみ人が精査

想定KPI

  • 配信の既読率／ニュース起点の商談化数（UC-05）
  • 比較表の更新頻度／変化点の検知数（UC-53）
