# 競合モニタリング Skill（UC-05 ＋ UC-53）

担当業界・主要クライアント・競合について、**定点で情報を収集・要約し、
出典リンク付きの週次ブリーフィング**を生成する Claude Cowork 向けスキル。
併せて、競合×指標の**ベンチマーク比較表を更新**し、変化点のみを通知する（UC-53）。

## なぜ Cowork なのか

UC-05 は適格性テスト（4-1）で **ルールA＝チャットで代替不可**（定期起動と配信の仕組みが必要）。
Cowork は Web 検索・Gmail・Notion 等のコネクタを横断して**エージェントとして一連の作業を実行**できるため、
「収集 → 検証 → 要約 → 配信」という UC-05/53 の連鎖の担当として最適。

## 監視対象の設定

はじめに `references/watchlist.example.md` を複製し、対象を定義する（無ければユーザーに質問して作る）：
- **業界**：担当インダストリと注目テーマ
- **クライアント**：主要アカウント（社名・IR/ニュースのURL）
- **競合**：ベンチマーク対象企業と、比較する指標（例：AI関連の発表、料金、提携、採用動向）

## 手順

1. **収集**：ウォッチリストの各対象について直近7日の動きを Web 検索で集める。
   一次情報（公式リリース・IR・決算資料・当局発表）を優先し、まとめ記事は裏取りの起点に留める。
2. **検証**（重要 / ガバナンス）：
   - 各項目に**原文リンクを必ず付ける**。原文が確認できない情報はブリーフィングに載せない。
   - **財務・シェア等の数値は一次情報（決算資料等）に当たる**。二次まとめの数値を根拠にしない。
   - 重要な示唆が判断に影響する場合は、`references/source_policy.md` の出典ランク（S/A/B/C）を併記する。
3. **要約**：`references/briefing_template.md` の様式で、対象ごとに「事実 → なぜ重要か → 示唆/次の一手」を3点以内で。
   推測は「（推測）」と明示し、事実と混ぜない。
4. **ベンチマーク更新（UC-53）**：`references/benchmark_table.md` の競合×指標の表を今回の情報で更新し、
   **前回からの変化点だけ**を「変化サマリ」として冒頭に出す。
5. **配信**：ユーザーの指定に応じて出力する（既定は Gmail 下書き）。
   - **Gmail**：ブリーフィングを本文にした**下書きを作成**（自動送信はしない。送信は人が承認）。
   - **Notion**：週次ページを作成し、ベンチマーク表を更新。
   - **チャット**：Markdown でその場に表示。

## 出力ポリシー（元資料のガバナンスに準拠）

- **誤要約リスク対策**：全項目に原文リンク必須（UC-05 のガバナンス注記）。
- **一次情報主義**：数値は決算資料等の一次ソース（UC-53 のガバナンス注記）。
- **人間最終判断（A1）**：配信は下書きまで。送信・社外共有は人が承認する。
- **区分（G1）**：非公開の顧客秘密は本スキルの対象外（公開情報のみを扱う）。

## 定例実行

「毎週月曜の朝にこのスキルを実行して」のように依頼されたら、
週次のスケジュール実行として設定する（Cowork のタスク/ルーティン機能）。
各回、前回との**変化点**を必ず冒頭に出し、既読負荷を下げる。

## 想定KPI

- 配信の既読率／ニュース起点の商談化数（UC-05）
- 比較表の更新頻度／変化点の検知数（UC-53）
