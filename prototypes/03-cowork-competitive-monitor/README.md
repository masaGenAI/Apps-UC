# Prototype 03 — 競合モニタリング Skill（Claude Cowork）

> **元ユースケース：UC-05 業界ニュース・競合モニタリング配信 ＋ UC-53 競合ベンチマーク自動更新** ／ ○第2波・PT6
> 担当業界・クライアント・競合の動きを定点で収集・要約し、**出典リンク付き週次ブリーフィング**を生成して配信する Cowork スキル。

## なぜ「Claude Cowork」で作るのか

UC-05 は適格性テスト（4-1）で **ルールA＝チャットで代替不可**（定期起動と配信の仕組みが必要）と判定。
Cowork は **Web検索・Gmail・Notion などのコネクタを横断してエージェントとして作業を完結**できるため、
「収集 → 検証 → 要約 → 配信」という UC-05/53 の一連の流れをそのまま担える。
（同じ変換ロジックを、UC-16 のように *コード資産* として持つべきものは Claude Code＝Prototype 02 が担当。役割分担が異なる。）

## 構成

```
03-cowork-competitive-monitor/
├── SKILL.md                      … スキル本体（Cowork がこの手順で実行）
└── references/
    ├── watchlist.example.md      … 監視対象の定義テンプレ（複製して使う）
    ├── briefing_template.md      … 週次ブリーフィングの出力様式
    ├── benchmark_table.md        … 競合×指標の比較表（UC-53・常時更新の資産）
    └── source_policy.md          … 出典ランク S/A/B/C と検証ルール
```

## 使い方（Cowork 上）

1. このディレクトリを Cowork のスキルとして読み込む。
2. `references/watchlist.example.md` を複製し、担当業界・クライアント・競合を記入。
3. 「competitive-monitor を実行して」または「今週の競合ブリーフィングを作って」と依頼。
4. Cowork が収集→検証→要約→ベンチマーク更新を行い、**Gmail 下書き**（既定）か **Notion ページ**として出力。
5. 定例化する場合は「毎週月曜の朝に実行して」と依頼し、週次ルーティンに設定。

## 元資料のガバナンス原則への対応

| 原則 / 注記 | 本スキルでの実装 |
|---|---|
| UC-05「誤要約リスク → 原文リンク必須」 | 全項目に一次情報リンクを必須化。確認できない情報は載せない |
| UC-53「財務数値は一次情報に当たる」 | 数値は決算資料等の一次ソースで検証。二次まとめは根拠にしない |
| **A1**（最終責任は人間） | 配信は**下書きまで**。送信・社外共有は人が承認 |
| **G1**（データ投入区分） | 公開情報のみを対象。顧客秘密は投入しない |
| **G6**（二モデル検証・任意） | 重要示唆は2モデルに独立投入し相違点のみ人が精査 |

## 想定KPI

- 配信の既読率／ニュース起点の商談化数（UC-05）
- 比較表の更新頻度／変化点の検知数（UC-53）
