# Prototype 02 — 会議自動化パック（Claude Code）

> **元ユースケース：UC-16 会議自動化パック（議事録・タスク抽出）** ／ ★第1波・PT6
> 文字起こしを入力に、**議事録・決定事項・タスク（担当/期限/優先）** を1コマンドで生成する Claude Code 向けキット。

## なぜ「Claude Code」で作るのか

UC-16 は適格性テスト（4-1）で **ルールA＝チャットで代替不可** と判定されたユースケースです。
判定理由は「Teams＋Power Automate の仕組み構築、録音同意と保存期間の設計、全社標準化がすべて必要」。
つまり *会話1回で終わらず、コード化・自動化・様式の資産化* が要る領域であり、
CLI/パイプラインとして書き起こす Claude Code がふさわしい担当です。

## できること

```
python meeting_pack.py <文字起こし.txt> [オプション]
```

入力（プレーンテキストの文字起こし）→ 出力2ファイル：

| 出力 | 内容 |
|---|---|
| `<title>_minutes.md` | 議事録：要旨・決定事項・タスク表・論点・次回への問い＋**人間レビュー欄** |
| `<title>_tasks.json` | 構造化データ（決定/タスク/論点/匿名化対応表）。後段の自動化に接続可能 |

## 使い方

```bash
# 1) デモ（APIキー不要・ネット不要。成果物の“形”を確認）
python meeting_pack.py sample_transcript.txt --offline -o out

# 2) 実運用（Claude で高精度に構造化）
export ANTHROPIC_API_KEY=sk-ant-...
python meeting_pack.py sample_transcript.txt -o out

# 3) 秘匿情報に配慮して人名を匿名化してから処理（G1）
python meeting_pack.py sample_transcript.txt --redact -o out
```

- `--offline` … LLMを使わず内蔵のルールベースで抽出。**CI やデモ用**（抽出はあくまで簡易）。
- `--redact` … 「氏名＋敬称」を `[PERSON_n]` に置換し、対応表を JSON に保存（G1: 投入区分への配慮）。
- 環境変数 `MEETING_PACK_MODEL` でモデル指定可（既定 `claude-sonnet-4-5`）。

## 元資料のガバナンス原則への対応

| 原則 | 本キットでの実装 |
|---|---|
| **G5**（製品交代に耐える） | プロンプト・出力様式を Markdown/JSON の汎用形式で外部化。ツールを替えても様式は不変 |
| **G1**（データ投入区分） | `--redact` で人名を匿名化してから送出。対応表は手元に保持 |
| **A1**（最終責任は人間） | 議事録に必ず「レビュー担当」欄を出力し、無断承認を防ぐ |
| **G2**（高リスクは人間最終判断） | タスク/決定は *提案* であり、確定は人の承認前提であることを明記 |

## 想定KPI（UC-16）

- 議事録作成の所要時間削減率（Before実測必須）
- タスクの取りこぼし率／期限遵守率の改善
- 会議あたりのフォローアップ漏れ件数

## 次の一手（本番化への道筋）

このプロトタイプは *コアの変換ロジック* です。全社展開時は：
1. Teams 会議の文字起こしを **Power Automate** で本スクリプトに連携（定期/イベント起動）
2. タスク JSON を Planner / Teams タスクへ自動起票
3. 録音同意・保存期間の設計（統制）を UC-16 本体の要件として付帯
