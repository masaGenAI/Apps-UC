3ヶ月でAIアプリを20本、作り切る計画。

1人＋AIの専念体制（週30–40h）で、外販プロダクト・コンサルワーク高速化・セキュリティ/ガバナンスを横断して20本を出す。 鍵は「数を狙う」ことではなく、共通基盤で作る手間を1回に畳み、社内標準プロセスのゲートで質を落とさないこと。 各アプリは要件定義（P1）からリリース（P5）・定着（P6）まで同じ型で通す。

00結論と現実的な前提

「20本」は達成可能。ただし成立条件がある。ここを外すと数は出ても“売れない・使われない”棚卸しになる。

成立させる3条件
  • 共通基盤を先に作る（W1–2）。20本の8割は同じ骨格（型キット＋HTML＋PDF出力＋軽量バックエンド）を使い回す。
  • Tier分け。TierA=HTML＋LLMキット（2–4日）、TierB=軽量バックエンド付き（6–10日）。全部をSaaS化しない。
  • ゲートで質を担保。社内標準のP1–P6を各アプリに適用し、特にデータ区分（P1）とセキュリティ/ガバナンス審査（P5前）は非通過なら出さない。
正直なトレードオフ
  • 1人＋AIで「20本すべてを本格SaaS」は不可能。だから買い切り／診断→コンサル誘導／社内利用を軸に、運用負荷の重いサブスクは後回し。
  • 質が危うくなったら数より質。最終手段は「14本を磨き上げ＋6本はβ公開」に切替える判断基準を持つ（後述）。
  • 契約書/DD/PIIなど高リスク領域は閉域前提・社内先行。安易に外販しない。

01共通基盤（W1–2の投資が20本を軽くする）

最初の2週間で「毎回作るもの」を一度だけ作る。以降の各アプリはこの上に乗せるだけにする。

アプリ基盤 shell

  • デザインシステム／テーマ（ラボ共通）
  • PDFレポート出力（印刷最適化）
  • 入力→プロンプト生成→JSON可視化の共通部品
  • GitHub Pages / Artifact 配布

「型」キット枠 kit

  • system-prompt＋rubric.json＋会社ポリシー差し込みスロット
  • 証跡E0–E5・ゲート・4層出力の共通仕様
  • ①アセスメントで実証済み → 横展開

軽量バックエンド TierB

  • 認証・保存・課金：Supabase＋Vercel
  • 買い切りライセンスキー（Gumroad/Lemon Squeezy）
  • サーバレスでPDF生成・ファイル処理

評価・レッドチーム quality

  • 評価セット雛形（代表20–50件・機密除去）
  • LLM-as-judge校正＋一貫性テスト
  • プロンプトインジェクション点検チェックリスト

GTM・法務 go-to-market

  • ランディング／価格ページ雛形
  • 利用規約・プライバシー・データ取扱いの標準文
  • 「診断→コンサル」導線テンプレ

資産ライブラリ reuse

  • プロンプト・rubric・様式を版管理（UC-22相当）
  • 各アプリの学び→基盤へ還流
  • 他社インスタンス量産の元

05収益化とGTM

運用負荷の重いサブスクは当面避け、買い切り・診断→コンサル誘導・社内利用の3本柱で回す。

買い切り／ライセンス

キット・テンプレ・TierBツールを買い切り販売（Gumroad/Lemon Squeezyでライセンスキー発行、運用最小）。まずは A05/A07/A09/A11/A14 など単体で完結するもの。

診断→コンサル誘導

無料/低額の診断（A01/A02/A20）を入口に、深掘りレポート＝有料、さらに改善支援＝コンサル案件へ。Rise文脈の主力導線。CTAと事例を各診断に標準搭載。

社内利用（デリバリー高速化）

A10/A12/A13/A15/A16/A18 は自社案件で先に使い、実測（時間削減・品質）を取得。この実測が外販の根拠と価格の裏付けになる。

価格の目安（仮説・要検証）：買い切りキット ¥9,800–¥49,800／診断 無料〜¥30,000（深掘りレポート）／チーム版・社内導入は個別見積。まず1本で価格テストしてから横展開する。

06ガバナンス・品質バー（全アプリ必須）

セキュリティ/ガバナンスは加点でなくゲート。1本でも事故れば全体の信頼を失うため、ここは妥協しない。

データ取扱いの既定

  • TierA：入力はブラウザ内処理・非保存を既定に。
  • TierB：リージョン管理・学習利用オフ・保存最小化。顧客秘密/個人情報は原則扱わない（扱うA06/A18は閉域・同意・匿名化前提）。
  • 「型」の会社ポリシー差し込みで、各社基準に適合。

リリース前チェック

  • 外部入力を扱うアプリはプロンプトインジェクション点検必須（A05の自己適用）。
  • PII・著作権/ライセンス・来歴表示・人間最終判断の確認。
  • 評価の妥当性・一貫性・公平性（測定基準に準拠）。
  • 規約・プライバシー・免責の明記（人事評価に直結させない等）。

07リスクと対処

リスク影響対処
1人のキャパ超過遅延・品質低下共通基盤の徹底再利用／TierA比率を上げる／週次で残ゲートを可視化
数優先で浅くなる売れない・使われないDoDとゲートを死守。危険時は「14本磨き＋6本β」へ切替（判断基準：W8終了時に良品6本未満なら数を落とす）
高リスク領域（契約/DD/PII）情報事故・信頼失墜閉域前提・社内先行・限定外販。A06/A18は法務レビュー必須
課金/税/サポート運用負荷買い切り＋外部決済で運用最小化。サブスクは実需確認後
モデルコスト/変動採算・可搬性プロンプト/様式を汎用形式で外部化（G5）。代替LLMで動作確認
評価の主観・不安定採点の信頼性評価セット＋校正＋一貫性テスト。診断は「証跡不足＝暫定」を明示
